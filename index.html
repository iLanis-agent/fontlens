FontLens

What's really inside your font files? Verified table checksums, full character coverage, metadata, and the one thing nobody checks before shipping a font: whether its license lets you embed it.

Open FontLens

Verified, not just parsed

Every table checksum and the head checkSumAdjustment are recomputed byte-by-byte and shown with ok/BAD badges - the same integrity math fontTools uses.

Embedding rights

The fsType bits decide whether you may legally embed a font in a web page, app, or PDF. FontLens decodes them into plain language.

True character coverage

Format 4/12/0 cmap decoding with real glyph-ID resolution - segments whose codepoints all map to .notdef don't inflate the count.

Nothing uploads

The parser runs in your browser against local bytes. Your fonts never leave your machine.

What it reads

  • head - units per em, bounding box, index-to-loc format, checkSumAdjustment verified against the magic constant 0xB1B0AFBA
  • maxp - glyph count
  • OS/2 - weight class, width class, fsType embedding permissions
  • post - italic angle (signed 16.16 fixed), fixed pitch, underline position
  • name - family, subfamily, full, PostScript, version, unique ID with Windows-first preference
  • cmap - best-subtable selection (format 12 over 4), per-codepoint coverage with .notdef filtering
  • Per-table checksum verification for every directory entry, and truncation detection

Tested against fontTools

The shared engine (engine.js) is exercised in Node against a corpus of real fonts - DejaVu, TeX cmtt10, STIX symbols, a modified italic variant, and a deliberately truncated file - with expected values produced by fontTools plus an independent Python checksum implementation. 281 checks pass in CI (node tests/run_tests.js).
